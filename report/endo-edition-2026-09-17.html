The five dark switches

Computer control is written, wired, and turned off at the server.

Muse ships its feature gates in a Meta config file (endo-values-public) that the app re-downloads on every launch. Five booleans in the hatch_desktop namespace decide whether Muse can operate the machine — and all five arrive false:

  • enable_computer_control false
  • endo_enable_screen_recording false
  • enable_browser_automation false
  • endo_system_run_sandbox_enabled false
  • endo_enable_computer_use_onboarding false

Source · Muse 1.0 MobileConfig cache ~/Library/Caches/com.meta.endo/MobileConfig/endo-values-public-956902cf.json, read Sept 17 2026. Values re-fetched from Meta every launch.

02

system.run · sandboxed execution

It can run programs — one at a time, on a leash.

> muse: system.run
  "Execute a single program with argv-style arguments.
   Shell operators, redirects, pipes, globbing, and
   environment expansion are not supported."

  "AppleScript (osascript / osacompile) and `open -a`
   app launches are REJECTED in background mode."

  gate: hatch_desktop:endo_system_run_sandbox_enabled = false

The design is deliberately narrow: no shell string, no -c, argv only — so pipes and redirects an app blocklist can’t see never run. It’s an execution primitive built for a careful rollout, not a terminal.

Source · strings in the Muse Mach-O binary (arm64, Developer ID “Meta Platforms, Inc.”), Sept 17 2026.

03

Vision · it wants to watch the screen

ScreenCaptureKit is linked. The overlay is coded. The grant is asked for.

The binary imports Apple’s modern screen-capture stack and the calls that request the permission at runtime — plus an on-screen “I’m looking” overlay and an accessibility-first click mode. Everything a computer-use agent needs to see a Mac is present:

  • SCShareableContent / SCStreamConfiguration linked
  • CGRequestScreenCaptureAccess linked
  • [ComputerUse] Display assertion acquired string
  • _showComputerUseOverlay string
  • _preferAXForComputerUseClicks string

Yet environment.describe reports screen_recording: false even after the macOS permission is granted — because the gate above overrides it.

Source · linked symbols + strings, Muse 1.0 binary, Sept 17 2026.

04

Browser automation

Muse can drive a Chromium over the DevTools protocol — on loopback.

A second withheld capability: the app carries browser-automation plumbing that speaks CDP to a local debug endpoint. The gate is its own flag, separate from computer control — a hint the two ship independently.

--remote-debugging-address=127.0.0.1

Paired with enable_browser_automation = false, this is the same shape as every agentic-browser feature of 2026: a headed browser the model steers, kept on localhost so nothing’s exposed.

Source · Muse 1.0 binary strings, Sept 17 2026.

07

Under the hood

The agent doesn’t run on your Mac. It runs in a Meta VM.

The reason a local flag can’t force computer-use on: the agent itself lives in a per-user cloud VM, reached over a Noise-encrypted WebSocket gateway. The Mac is a set of hands; the brain is server-side.

  • Per-user VM hatch.metaaivm.com
  • Transport Tigon HTTP · Noise wss gateway
  • Auth backend Meta “Proton” · api.meta.ai/proton
  • Chat / agent API hatch-api.meta.ai

The config that withholds computer-use rides the same edge as login and session-refresh — so it can’t be blocked without killing the app.

Source · launch-time DNS capture + binary transport symbols, Mac mini, Sept 17 2026.

08

The tell

Employees first. This is a staged rollout, not a dead feature.

Two flags in the same config give the release plan away — an onboarding flow that’s built but hidden, and an employee switch that ships in the public build:

hatch_desktop:endo_enable_computer_use_onboarding
hatch_desktop:voyager_is_employee

An onboarding gate implies a first-run “let Muse control your Mac” walkthrough already exists. An employee gate implies Meta staff are testing it now, ahead of a cohort rollout to everyone else.

Source · MobileConfig endo-values-public, Muse 1.0, Sept 17 2026.
